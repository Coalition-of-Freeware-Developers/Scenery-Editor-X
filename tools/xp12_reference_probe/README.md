# SEDX Reference Probe

An X-Plane 12 plugin that renders the XP12 parity scenarios and dumps X-Plane's art-control values, so Scenery Editor
X's emulation of X-Plane 12's look can be measured against X-Plane itself (plan
`plan/feature-xp12-environment-rendering-1.md`, Phase 1).

Scenario files, comparison tools and the calibration scenery live next to it:

| Path | What |
|---|---|
| `scenarios/xp12_parity.json` | The KSEA parity set (camera, date, time, weather, exposure lock). Generated by `scenarios/make_parity_scenarios.py`: edit the script, then run it. |
| `scenarios/xp12_airports.json` | The standard test airports, used for feature, performance and parity checks: KGON (Groton-New London), KDEN (X-Coder's Denver), KORD (O'Hare), KBOS (ZDP's Boston Logan), KBTV (Burlington). Per airport: a runway threshold and an aerial view at sun 40 deg (auto and locked exposure), low sun, night, haze, overcast, a wet runway, snow, winter noon, and a low water view for KGON and KBOS. Generated by the same script. |
| `render_scenarios.py` | Renders a scenario file in SEDX, one editor run per scenario, and reports load times, frame timings, GPU passes and peak memory per scenario and per airport. |
| `test_scenery/SEDX_Calibration/` | Material calibration tiles at KSEA (grey card, metalness and gloss ramps, `SUPER_ROUGHNESS`, LIT nits ramp, `WEATHER` masks). Generated by `test_scenery/make_calibration_pack.py`. |
| `../image_compare/xp_compare.py` | Compares the probe's screenshots with SEDX's captures (CIEDE2000, FLIP, luminance histogram, sky). |
| `../../docs/xplane/xp12_art_controls.txt` | The art-control names the probe dumps. |

## Build

Needs the X-Plane plugin SDK (XPLM 4.x, <https://developer.x-plane.com/sdk/plugin-sdk-downloads/>).

```bash
cmake -S tools/xp12_reference_probe -B build_linux_tests/probe -DXPLANE_SDK_DIR="<XPSDK folder>/SDK"
cmake --build build_linux_tests/probe --config Release
```

or configure the main tree with `-DSEDX_BUILD_XP_PROBE=ON` and `XPLANE_12_SDK` set. The build writes
`SEDXReferenceProbe/64/win.xpl` (`lin.xpl`, `mac.xpl`) plus `scenarios.json` (the parity set), `airports.json` (the
test airports), `art_controls.txt` and this README into the build folder.

## Install

1. Copy the `SEDXReferenceProbe` folder from the build folder to `X-Plane 12/Resources/plugins/`.
2. Optional: copy `test_scenery/SEDX_Calibration` to `X-Plane 12/Custom Scenery/` (first export its DSF with SEDX, see
   below) for the `ksea_calib_*` scenarios.
3. For references comparable with SEDX, turn MSAA off in X-Plane's graphics settings (SEDX's deferred path has none),
   and keep anything else off the screen: the Data Output tab's on-screen display, other plugins' messages
   (FlyWithLua) and the network-data notice end up in every screenshot.
   Scenery packs that replace library art are fine (AEP replaces `lib/airport/default_runways/*`, the runway and
   taxiway polygons): SEDX resolves the same library in the same `scenery_packs.ini` order. Plugins that animate
   scenery (Living Scenery Technology's vehicles and people) put objects SEDX doesn't draw into the shots, so compare
   regions clear of them.
4. Start X-Plane fresh for each run: an earlier probe build wrote `photometric/ev100`, which X-Plane then stops driving
   for the rest of the session.

## Run

Start X-Plane with any aircraft, then **Plugins > SEDX Reference Probe > Run all parity scenarios (KSEA)** or **Run all
test-airport scenarios** (the first scenario of either alone is there for a quick check). Scenarios run clear and dry
first, then hazy / foggy / overcast, then wet, then snowy (X-Plane takes minutes of sim time to melt snow and dry a
runway, so the order keeps one scenario's weather out of the next); within each of those groups an airport's scenarios
run together, so X-Plane loads each airport once per group. For each scenario the probe

1. moves the user to the scenario's airport (and waits for the scenery to load) and then out of sight behind the camera,
2. sets the date and time (`sim/time/*`), the weather (`sim/weather/region/*`: visibility, three cloud layers, rain,
   runway friction, snow cover, temperature; `update_immediately`), and the field of view,
3. holds the camera at the scenario's pose (`XPLMControlCamera`) and, for `ev100_lock` scenarios, clamps
   `photometric/ev100_min` / `_max` to the locked value (`photometric/ev100`, auto exposure's output, is only read);
   a scenario's `art_controls` (`{ "ssao/enable": 0 }`, names under `sim/private/controls/`) are set for that shot and
   put back after it (the `_noao` twins: X-Plane's ambient occlusion is the shot minus its twin; the `_nossr` twins,
   `debug/kill_ssr` 1, do the same for its screen-space reflections; SEDX's `--env-scenario` applies `ssao/enable` and
   `debug/kill_ssr` too),
4. waits `settle_frames` frames, takes a screenshot (`sim/operation/screenshot`) and copies it to
   `X-Plane 12/Output/sedx_probe/<id>.png`,
5. writes `<id>.json`: the scenario, what was applied, sun position, window size, weather as X-Plane reports it, and the
   value of every art control it could find (`sim/private/controls/<name>`, else `sim/private/stats/<name>`).

A log goes to `Output/sedx_probe/probe_log.txt` and X-Plane's `Log.txt`. For unattended runs put a file named
`autorun` into `Output/sedx_probe/` (with the word `quit` inside to exit X-Plane when done, `airports` to run the
test-airport set instead of the parity set); delete it afterwards, or every start runs again. A
`Output/sedx_probe/scenarios.json` (or `airports.json`) overrides the copy installed with the plugin.

## Render the same scenarios in SEDX

```bash
bin/SceneryEditorX.exe --env-scenario tools/xp12_reference_probe/scenarios/xp12_parity.json --env-scenario-index ksea_aerial_sunp40 --capture-png captures/ksea_aerial_sunp40.png
```

`--env-scenario-index` takes an index or an id. The editor opens the scenario's airport (and project, for the
calibration scenarios), renders at the scenario's size, waits until every placed object has loaded (payware airports
stream in for many seconds after they open; at most 7200 frames), then `settle_frames` (or `--capture-after-frames`),
writes the PNG plus `<id>_sky.png` and exits. Without `--capture-png` it stays open; `--reference-image <png>` with
`--reference-view split|difference|flicker` loads an X-Plane screenshot into the viewport's REFERENCE overlay (also in
the viewport toolbar).

A whole file in one go, with performance numbers (standard library Python; one editor run per scenario):

```bash
python -I tools/xp12_reference_probe/render_scenarios.py                                   # every test-airport scenario
python -I tools/xp12_reference_probe/render_scenarios.py "*_aerial_sunp40" "*_rwy_sunp40"  # ids or patterns
python -I tools/xp12_reference_probe/render_scenarios.py --scenarios tools/xp12_reference_probe/scenarios/xp12_parity.json
```

It runs `bin/SceneryEditorX` (the Release build; `--exe` for another) with `--perf-log --no-vsync --lock-camera`, and
writes `<id>.png` and `<id>.log` per scenario plus `summary.md` / `summary.json` into
`<editor cache>/scenario_captures/<scenario file name>/` (`--out` for another folder): per airport and per scenario the
load times (DSF overlay, base terrain, tile scenery, object placement, the whole airport), scene size, frame rate, CPU
work per frame (main thread update + UI plus render thread tick), the GPU passes and peak memory. `--extra "--no-water"`
passes more editor flags (A/B runs), `--summarize-only` parses the logs of an earlier run again.

## Compare

```bash
python -I tools/image_compare/xp_compare.py --references "<X-Plane 12>/Output/sedx_probe" --sedx captures --out parity_report
```

Writes `parity_report/report.html` and `summary.json`, and exits with 1 when a scenario breaks
`tools/image_compare/thresholds.json`. Needs `numpy`, `Pillow` and (for FLIP) `flip-evaluator`. The probe writes both
sets' references into the same `Output/sedx_probe`, told apart by their ids; for the test airports:

```bash
python -I tools/image_compare/xp_compare.py --references "<X-Plane 12>/Output/sedx_probe" --sedx "%LOCALAPPDATA%/SceneryEditorX/cache/scenario_captures/xp12_airports" --scenarios tools/xp12_reference_probe/scenarios/xp12_airports.json --only "^(kgon|kden|kord|kbos|kbtv)_" --out airports_report
```

## Calibration pack DSF

`make_calibration_pack.py` writes the tiles, textures and `SEDX_Calibration.edX`. Its DSF comes from SEDX's own
exporter (the pack folder is the project folder):

```bash
bin/SceneryEditorX.exe --project tools/xp12_reference_probe/test_scenery/SEDX_Calibration/SEDX_Calibration.edX --export-scenery
```

## Legal

The probe reads and writes only datarefs X-Plane exposes to plugins. Screenshots and dumps it produces are of
Laminar Research's software: keep them local (`%LOCALAPPDATA%\SceneryEditorX\cache\xp12_reference\`), never commit
them; commit only metrics (`summary.json`). See the plan's LEG-001.
