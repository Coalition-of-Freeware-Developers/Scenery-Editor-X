## Q1. Which user-visible settings exist and which art controls does each level set?

### Takeaway
settings.txt defines **15 UI settings** (prefs keys `renopt_*`), mapped by `SETTING_1` (one-key) and `SETTING_2` (two-key) tables onto ~45 art controls covering object/road/car/airport density, trees, draw distance/LOD, cloud resolution and quality, FSR 1 upscaling, SSAO (CACAO) quality, CSM shadows, MSAA, FXAA, texture resolution and anisotropy. There is **no UI setting for exposure, tone mapping, scattering, water, reflections, bloom or weather effects** in settings.txt — those are art controls with fixed defaults (plus separate exposure preferences, see Q4).

### Inferences
- The `fsr/lod_bias` values (-0.38/-0.58/-0.79/-1.0) appear to be AMD FSR 1.0's recommended mip biases for the Ultra Quality/Quality/Balanced/Performance scale factors (1.3x/1.5x/1.7x/2.0x), i.e. X-Plane uses FSR 1 spatial upscaling; `fsr/quality` counts down (3 = ultra quality .. 0 = performance). `reno/rcas_rat` + the pref `_rcas_ratio` is presumably the FSR RCAS sharpening strength. (Not verified against AMD docs in this session.)
- `hdr/msaa_hw` is a log2 sample-count index (1=2x, 2=4x, 3=8x); the log's "max samples : 3" for this RTX 3090 fits that encoding.
- `ssao/quality_level` 0..4 matches the enum string "lowest-low-medium-high-highest" found next to the CACAO panel, so UI "low" = CACAO "medium"(2), UI "medium" = "high"(3), UI "high"/"highest" = "highest"(4), with "highest" also dropping `ssao/downsample` to full resolution.
- Shadow level 0 omits `shadow/csm/far_limit_interior` (the line duplicates the exterior key) — likely a typo in Laminar's file; interior keeps whatever value the previous level/default left.
- For an editor's quality presets, the useful knobs are: CSM cascade count (1-4), far limit (120-1000 m), shadow map size (1024-4096), fade ratio (0.5-0.999); cloud buffer scale (0.2-0.5 of screen, capped 980/1920 px) and shadow steps (3-8); CACAO quality 2-4 and downsample; tree density (0.1-1.0) and LOD distance (4-18 km); LOD bias ratio 5 -> 1.

## Q2. Which art controls govern lighting, exposure/tone mapping, color, sky/atmosphere, fog, shadows, AO, reflections, water, rain/wet/ice/snow, seasons, lights, bloom/DOF?

### Takeaway
The 12.4.4-b4 binary contains about 2,077 relative `group/name` strings, of which roughly 1,000 fall in rendering/weather groups (lights 137, skyc 112, water 70, new_clouds 52, cloud 48, twxr 48, scattering 46, weather 40, hack/petr/wxr 40, volumetric 35, terrain 33, clouds 32, shadow 28, ssao 25, rain 24, ibl 23, …); some are `sim/private/stats/` counters rather than controls. The lighting core is a **photometric HDR pipeline**: sun/moon illuminance in lux (`lighting/E_sun_lx`, `E_moon_lx`), luminance references in nits (`*_ref_nts`, `moon/nits`, `stars/gain_photometric`), an **EV100 camera** (`photometric/ev100*`) driven by a histogram auto-exposure (`autoexposure/*`), **exposure fusion** (`exposure_fusion/*`), a tone mapper (`tonemap/mode`) and an SDR **color-management grade** (`color_management/sdr/*` slope/offset/power/saturation). Atmosphere is a physical scattering model (`scattering/*`, `atmo/*` Rayleigh/ozone) plus per-sky-condition multipliers (`skyc/*`), with froxel volumetric fog (`volumetric/fog/*`). Weather surfaces use `twxr/*` (rain darkening, ice and snow decals), `wxr/*_now` state, and keyframed in/out ramps. There are **no film grain, vignette (as a control), chromatic-aberration or LUT art controls**.

### Inferences
- The likely shipped lighting chain for reproduction: scene radiance in nits (sun illuminance `E_sun_lx`, sky from `scattering/*` + `atmo/*`), multiplied by sky-condition ratios `skyc/{direct,ambient,tone}_ratio_<condition>` blended by weather -> EV100 from art-set curves clamped to [`ev100_min`, `ev100_max`] with `ev100_bias` -> histogram auto-exposure (`autoexposure/*`, adaptation `exposure/speed_up|down`) -> exposure fusion (multi-exposure blend for interiors, `exposure_fusion/dis_near|dis_far` distance gates) -> tonemap (`tonemap/mode`; AgX since 12.2) -> SDR grade (`color_management/sdr/*`, ASC-CDL-style slope/offset/power + saturation, plus `abney_correction` hue fix and `compression` gamut/highlight compression) -> sRGB.
- `photometric/ev100_mtr` probably is the metered EV and `ev100_mid` the mid-grey/target EV; `photometric/K` is likely the reflected-light meter calibration constant K (photographic exposure equation; 12.5 is common). Not confirmed.
- `skyc/raleigh_*`/`mie_*` per condition plus `scattering/override_turbidity_t` and `override_visibility_m` suggest haze/aerosol density is driven from visibility (Mie) per weather class; a Vulkan editor can approximate by mapping visibility to Mie density.
- `wxr/rain_now`, `puddles_now`, `snow_now`, `ice_now`, `seasonal_now` sit in the Weather art-control block next to the `twxr` tuning, so they are most likely the current surface-state values the terrain/material shaders consume (and art-control overrides of them). Community scripts reportedly write them to force snow/wet looks, but that was not verified in this session.
- The `hack/petr/wxr/kf/*_in_N/_out_N` sets (5 points each for rain, puddles, ice, snow) look like piecewise-linear keyframe curves mapping a weather input to the applied surface amount.
- Season appears to be a continuous `season_rat` in [0,1] fed to vegetation (and terrain via `season_ref` textures), while libraries pick discrete spr/sum/fal/win exports.
- The cloud buffer at 960x540 for a 1920x1080 window matches `cloud/resolution_scale 0.50` at Cloud quality 2; the 256x256 environment probe context is presumably `lighting/probe_resolution`.

### Gaps
- Default values of nearly all of these controls are not readable from files; they need DataRefTool in a running 12.4.4 sim (not allowed here).
- `tonemap/mode` enum values (which index is AgX, which legacy curves remain) are not stated in any string.

## Q3. Which datarefs expose current weather-surface state (wetness, puddles, snow, ice) and season state?

### Takeaway
Public, writable surface-state datarefs are **`sim/weather/region/runway_friction`** (enum 0-15: dry, wet 1-3, puddly 4-6, snowy 7-9, icy 10-12, snowy/icy 13-15), **`sim/weather/region/snow_cover`** (0-1 ground snow cover) and **`sim/weather/region/rain_percent`** (0-1). Camera-local precipitation is in `sim/weather/view/*_ratio`. There is **no public season dataref**; season must be derived from `sim/time/local_date_days`/`zulu_date_days` plus latitude, with private art controls `wxr/seasonal_now` and `wxr/{rain,puddles,snow,ice}_now` holding the internal state.

## Q4. Which values are the defaults a typical user sees, and what ranges do the tables show?

### Takeaway

Community scripts record stock 12.0x values for exposure (EV100 5-15), auto-exposure gains, ozone and stars; these are older than 12.4.4 and should be treated as approximate.

### Inferences
- Ranges from the tables (file-sourced) are the safest quality-preset anchors for an editor; the community stock values are pre-12.2 for clouds and partly pre-12.2 for exposure, so they may be off for 12.4.4 (the 12.2 overhaul changed clouds, exposure and colour). Treat EV100 5-15 and `E_sun_lx` ~115,000 lx as a starting point only.
- The `_exp_*` prefs (auto-exposure mode, radius 0.33, speed-up/down presets 2) look like the user-facing exposure options added around 12.2 and probably feed `debug/histo_mode` / `histo_spot_radius` and `exposure/speed_up|down`; the mapping is not in settings.txt.

### Gaps
- Live default values for 12.4.4-b4 (most art controls, `tonemap/mode`, `color_management/sdr/*`, `skyc/*` ratios, `twxr/*`) could not be read without running the sim.
- The UI-to-art-control mapping for the exposure preferences (`_exp_autoexp_mode`, `_exp_radius`, `_exp_speed_*_pres`) is not in settings.txt or any other readable file.
- 12.4.3 vs 12.4.4-b4 differences in art-control names are unknown; the log is 12.4.3 but the strings are 12.4.4-b4.
